# Dota 2 Analytics

Веб-приложение аналитики матчей **Dota 2** для игроков в **Turbo**. Главная
особенность — оценка качества игрового опыта («Качество матча»): насколько
матч был равным, увлекательным, давал ли возможность влиять на происходящее и
насколько полезно взаимодействовали союзники. Вторая метрика — оценка
качества собственной игры. Плюс стандартная статистика: история Turbo-матчей,
подробная страница матча, составы, предметы и события.

Приложение **полностью статическое**: вся бизнес-логика, получение и
нормализация данных, расчёт оценок и пользовательские настройки выполняются
в браузере. Подходит для публикации на GitHub Pages. Backend, базы данных,
обязательные API-ключи и сторонние сервисы аналитики не используются.

## Архитектура

```
src/
  app/                  # роутинг (hash), сессия Steam
  components/
    ui/                 # UI-примитивы (Button, Card, Badge, Loading, LoadStages)
    media/              # EntityIcons (HeroIcon/ItemIcon/PlayerAvatar), ExternalLinkIcon
    StateViews.tsx      # скелетоны, ошибки, пустые состояния
  pages/                # Landing, Dashboard, Match, About
  features/
    steam-login/        # redirect URL Steam OpenID, разбор callback, SteamID64↔Steam32
    match-history/      # список Turbo-матчей, фильтры, сортировка, пагинация
    match-details/      # составы, графики, предметы, события
    analytics/          # карточки двух оценок
    feedback/           # субъективная оценка (localStorage)
  services/opendota/    # OpenDotaClient: HTTP, кэш, rate limiter, обработка ошибок
    client.ts           # единственный вход в сеть OpenDota
    cache.ts            # кэш память + localStorage (ключи, TTL, инвалидация)
    rateLimiter.ts      # очередь: интервал стартов, параллелизм, пауза после 429
    ttl.ts              # ВСЕ TTL кэша централизованно
  domain/               # модели приложения и MatchMapper (нормализация ответов)
  analytics/            # чистые функции оценок (без React и сети)
    experience-score/   # Match Experience Score
    player-performance/ # Player Performance Score
    normalization.ts    # шкалы и ограничения
    dataCoverage.ts     # полнота данных
    summary-scores.ts   # приблизительные оценки для списка
    config.ts           # ВСЕ веса и пороги (настраиваются централизованно)
  i18n/metrics.ts       # русские подписи статистики и событий + fallback
  hooks/, lib/          # useAsync, форматирование, storage, externalLinks, imageUrls
  test/                 # Vitest-тесты и фикстуры JSON
docs/score-model.md     # формулы, пороги, ограничения моделей
```

Обязательные границы модулей: `SteamLogin` (redirect/callback),
`OpenDotaClient` (запросы), `MatchMapper` (нормализация),
`MatchExperienceScore`, `PlayerPerformanceScore`, `DataCoverage` — расчёты
вынесены из JSX и тестируются без браузера.

### Используемые API

| API | Использование | Ключ |
|---|---|---|
| [OpenDota API](https://docs.opendota.com/) | профиль, история Turbo, детали матча, справочники | не требуется (есть лимиты частоты, HTTP 429) |
| [Steam OpenID](https://partner.steamgames.com/doc/features/auth) | вход: перенаправление на `steamcommunity.com/openid/login` | не требуется |

Эндпоинты: `GET /players/{id}`, `GET /players/{id}/matches?game_mode=23&limit=20&significant=0&offset=0`,
`GET /matches/{id}`, `GET /constants/heroes|items|game_mode|lobby_type`.
SteamID64 → Steam32: вычитание константы `76561197960265728` через `BigInt`
(`src/features/steam-login/steamId.ts`); обратное преобразование `steam32ToSteamId64`
используется для внешней ссылки на Steam-профиль.

## Кэш данных и лимиты запросов

Все запросы к OpenDota идут **только через один `OpenDotaClient`**
(`src/services/opendota/client.ts`): ни один компонент не обращается к API напрямую.

### Rate limiter

- Очередь общая для экранов, фоновых эффектов и кнопок: не чаще одного нового
  запроса каждые **1.3 с**, параллелизм ограничен **2** одновременными запросами
  (`src/services/opendota/rateLimiter.ts`, параметры конфигурируемы).
- Одинаковые одновременные запросы дедуплицируются через один in-flight Promise
  (защита от cache stampede).
- **HTTP 429**: учитывается заголовок `Retry-After` (секунды или HTTP-дата); без
  него — экспоненциальный backoff с jitter. Пауза останавливает **всю** очередь,
  чтобы не крутиться в тесном цикле.
- Сетевые сбои и **5xx** повторяются максимум **2 раза**; прочие 4xx (404/401/403)
  не повторяются автоматически.
- `AbortController`-таймаут (15 с) на каждый реальный запрос.
- `POST /request/{match_id}` (платный разбор реплеев) **не вызывается никогда**.

### Кэш

Кэш двухуровневый: память текущей сессии + `localStorage` (работает после
перезагрузки страницы до истечения TTL). Это **клиентский** кэш конкретного
браузера: он снижает число запросов этого пользователя, а не всех посетителей
сайта (GitHub Pages не даёт общей серверной кэш-памяти). Ключ включает метод,
endpoint, account ID / match ID и все существенные query-параметры — страницы
истории и разные пользователи не конфликтуют. Ошибки, 429 и 5xx в кэш
не записываются. Объём ограничен, просроченные записи вычищаются.

TTL заданы централизованно в `src/services/opendota/ttl.ts`:

| Тип данных | TTL |
|---|---:|
| Справочники (герои, предметы, режимы, лобби) | 7 дней |
| Профиль игрока | 4 часа |
| История матчей | 5 минут |
| Полностью обработанный матч | 7 дней |
| Неполный / ещё не обработанный матч | 5 минут |

Оценки не кэшируются отдельно: они пересчитываются в браузере из нормализованных
данных при каждом открытии, поэтому при обновлении матча пересчитываются
автоматически.

**Принудительное обновление** (кнопка «Обновить анализ» на странице матча):
инвалидирует **только** запись `GET /matches/{match_id}` в памяти и в
`localStorage`, выполняет новый сетевой запрос в обход кэша и сохраняет свежий
ответ с корректным TTL. Справочники, история и кэш других матчей при этом
**не удаляются**; субъективная оценка пользователя не затрагивается. При ошибке
обновления прежние данные остаются видимыми, а ошибка показывается отдельным
баннером (не записывается в кэш как данные).

Очистить локальный кэш можно в разделе **«Методика» → «Локальный кэш данных»**.

## Иконки, подписи и внешние ссылки

- **Иконки**: герои и предметы грузятся с официального CDN Valve
  (`cdn.cloudflare.steamstatic.com/…/dota_react/…`), аватары — из
  `profile.avatarfull` ответа OpenDota. При ошибке CDN показывается локальный
  SVG-плейсхолдер (`src/assets/placeholder.svg`); повторная ошибка не создаёт
  цикл. Компоненты: `HeroIcon`, `ItemIcon`, `PlayerAvatar`
  (`src/components/media/EntityIcons.tsx`). Сбой image-CDN не блокирует аналитику.
- **Подписи**: русские подписи статистики и событий — типизированный словарь
  `src/i18n/metrics.ts` (собственные формулировки проекта; raw key вида
  `snake_case` не выводится, неизвестный ключ получает человекочитаемый fallback).
  По правке 01 к итерации 02 (`spec/iteration-02-amendments.md`) **названия
  героев, предметов и способностей остаются английскими**, как в официальных
  данных OpenDota/Valve; русский язык сохраняется для описаний, подписей и
  сообщений. Словарей русских названий сущностей и сторонних сервисов
  локализации нет.
- **Внешние ссылки** строятся централизованно в `src/lib/externalLinks.ts`
  с валидацией: матч — Dotabuff/OpenDota, игрок — Dotabuff/OpenDota/Steam
  (только по валидному SteamID64), герой — Dotabuff/Liquipedia, предмет —
  Dotabuff. Слаги выводятся из официальных английских названий детерминированным
  преобразованием (проверено на реальных ответах API); при некорректном входе
  возвращается `null` и ссылка не показывается — URL наугад не генерируются.
  Все внешние ссылки открываются в новой вкладке
  (`target="_blank"`, `rel="noopener noreferrer"`, с подписью `aria-label`).

## Вход через Steam и его ограничения

**Важно.** Приложение использует упрощённый клиентский сценарий Steam OpenID
**без серверной проверки подлинности ответа** (без проверки подписи `sig`).

- Сайт статический и не имеет backend, поэтому проверить подпись криптографически
  негде.
- Параметры возврата (`openid.claimed_id` и др.) **можно подделать**: форматная
  проверка в коде (`parseSteamCallback`) гарантирует только корректность формата
  идентификатора, а **не** то, что владение аккаунтом подтверждено.
- Это приемлемо только потому, что приложение использует ID **исключительно для
  выбора публичного профиля** и не предоставляет защищённых функций, прав доступа
  или закрытых данных.
- Серверные сессии, пароли Steam, cookies, access tokens и API-ключи
  **не сохраняются**. Профиль хранится в `localStorage`.

Сценарий: кнопка «Войти через Steam» → редирект на официальный endpoint
Steam → возврат на `return_to` с `openid_callback=1` → извлечение 17-значного
SteamID64 из `claimed_id` → преобразование в Steam32 → сохранение профиля →
загрузка данных OpenDota → очистка `openid.*`-параметров из адресной строки.
Отмена входа обрабатывается отдельно (`openid.mode=cancel`).

> **Ручная проверка required:** сам сценарий входа нельзя проверить
> автоматически в тестовой среде — он требует реального аккаунта Steam.
> Тесты покрывают построение URL, разбор callback, отмену и подделку параметров.
> Проверьте вход вручную после разработки: `npm run dev` → `http://localhost:5173`.

## Модели оценок (кратко)

Обе метрики — **экспериментальные, V1**, с прозрачными формулами, объяснением
факторов, покрытием данных и возможностью **отказаться от итогового балла**
при недостаточной полноте. Отсутствующие поля никогда не подменяются нулями.

### Качество матча (Match Experience Score)

| Компонент | Вес |
|---|---:|
| Равенство и напряжённость | 30% |
| Возможность влиять на игру | 25% |
| Полезность союзников | 25% |
| Темп и вовлечённость | 20% |

- Равенство оценивается **только по временным рядам** `radiant_gold_adv` /
  `radiant_xp_adv`; без рядов компонент недоступен (конечный счёт не используется).
- Недоступные компоненты исключаются, веса перераспределяются; при покрытии
  **ниже 50%** итог не рассчитывается.

### Качество собственной игры (Player Performance Score, Turbo)

| Компонент | Вес |
|---|---:|
| Экономика и темп | 20% |
| Командные сражения | 25% |
| Цели и реализация преимущества | 20% |
| Выживаемость и решения | 15% |
| Полезность для команды | 10% |
| Эффективность предметов и сборки | 10% |

Не зависит только от победы и не сводится к KDA; роли 1–5 в MVP не
определяются. Правила расчёта каждого компонента и пороги — в
**[docs/score-model.md](docs/score-model.md)**.

Субъективная оценка «Как тебе матч?» (4 шкалы 1–5) хранится только в
`localStorage` и **не объединяется** с автоматическими оценками.

## Тесты

```powershell
npm run test
```

Покрыто (**161 тест**, без обращений к сети и CDN):

1. Преобразование SteamID64 → Steam32 (BigInt, границы, ошибки) и обратное
   Steam32 → SteamID64;
2. Формат идентификаторов (`isValidSteamId64`);
3. Успешный возврат Steam, отмена, некорректные параметры, подделка callback;
4. Определение стороны (слоты 0–127 / 128–255) и победы по `radiant_win`;
5. Пустая история и все классы ошибок OpenDota (429/401/403/404/5xx, сеть,
   CORS-подобные сетевые сбои, некорректный JSON, «не обработан», приватность);
6. Нормализация отсутствующих полей (не заменяются нулями);
7. Каждая формула Match Experience Score;
8. Каждая формула Player Performance Score;
9. Перераспределение весов при неполных данных;
10. Отказ от итогового балла при покрытии < 50%;
11. Граничные условия: нули, короткий матч, отсутствие командных боёв,
    недоступные метрики, leaver_status;
12. Пустые состояния, ошибки загрузки, скелетоны, субъективная оценка (RTL);
13. Кэш: ключ (метод/endpoint/параметры/пользователь), TTL и истечение
    (fake timers), персистентность в localStorage, версия схемы, лимит записей,
    точечная инвалидация (один матч не трогает справочники и историю);
14. Rate limiter: интервал между стартами, параллелизм, пауза после 429,
    FIFO-порядок, устойчивость после ошибок;
15. Клиент: дедупликация in-flight запросов, force-обновление одного матча
    (справочники/история остаются в кэше), короткий TTL неполного матча;
16. HTTP 429: `Retry-After` в секундах и HTTP-датой, экспоненциальный backoff,
    ограниченное число повторов, не-повторяемость 4xx;
17. `useAsync`: игнорирование устаревшего результата при смене ключа,
    сохранение данных при обновлении, ошибка обновления без вечного спиннера,
    однократный автозапуск на ключ (нет запросов на каждый рендер);
18. Иконки: URL CDN, локальный fallback при ошибке загрузки, отсутствие цикла
    onError, alt/loading;
19. Русские подписи известных метрик и fallback для неизвестного ключа
    (без `undefined`/`NaN`/`[object Object]`/сырого snake_case);
20. Генерация внешних URL (матч, игрок, Steam, герой, предмет) и отказ
    от некорректных ID/slug (`null` вместо сомнительной ссылки).

Фикстуры JSON: `src/test/fixtures/` — успешно загруженный Turbo-матч
(реальный обработанный ответ), неполный ответ и ошибка API.

## Публикация через GitHub Pages

1. Залейте репозиторий на GitHub.
2. **Settings → Pages → Source**: выбрать *GitHub Actions*.
3. Workflow `.github/workflows/deploy.yml` при пуше в `main`/`master`
   выполняет `lint`, `test`, `build` и публикует `dist/`.
4. Базовый путь Vite вычисляется как `BASE_PATH=/{имя-репозитория}/` прямо в
   workflow — имя репозитория **не зашито в исходники**. Для публикации в корне
   домена задайте `BASE_PATH: "/"`.
5. Callback Steam: `return_to`/`realm` строятся из текущего адреса с учётом
   `import.meta.env.BASE_URL`, поэтому работают и на
   `https://<user>.github.io/<repo>/`. В Steam-настройках доверенного домена
   укажите свой домен, если понадобится расширенная валидация.

Ручной запуск: вкладка **Actions → Deploy to GitHub Pages → Run workflow**.

## Устранение распространённых ошибок

| Симптом | Причина / решение |
|---|---|
| «Превышен лимит запросов OpenDota» (HTTP 429) | Публичный API без ключа ограничен. Подождите и нажмите «Повторить запрос». |
| «Данные игрока скрыты настройками приватности» | В Dota 2 → Настройки → Персональные данные включите публичность истории матчей. |
| «Матч ещё не обработан OpenDota» | Данные появятся после обработки матча; приложение не запускает разбор реплеев намеренно. |
| Пустая история Turbo | Нет сыгранных Turbo-матчей или история закрыта. |
| Сетевая ошибка / CORS | Проблема доступа к `api.opendota.com`; проверьте соединение и блокировки. |
| Ошибка `npm run dev` — порт занят | `npm run dev -- --port 3000`. Привязка входящего порта меняется на Docker-хосте/в интерфейсе среды исполнения, а не в коде приложения. |
| Белый экран на GitHub Pages | Проверьте, что выбран источник Pages = *GitHub Actions* и `BASE_PATH` соответствует пути репозитория. |
| Вход через Steam не возвращается | `return_to` должен совпадать с реальным адресом (включая `/repo/` для Pages). |
| Оценки показывают «—» | Недостаточно данных матча (список «Нет данных» в карточке оценки). |
